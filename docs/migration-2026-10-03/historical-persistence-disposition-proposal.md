## Finite permitted archival proposal and proof obligations

No family gains unrestricted compatibility. For each retained private reader, parent must name one closure owner, exact callers, allowed original row versions, byte/quota caps, corruption/ambiguity behavior, and terminal lifetime. Proposed smallest seams:

1. #770: remove unused legacy topic Registry/store production entry points only after exact private old-row reader/hold policy is accepted. Keep legacy CF opening and reservations; isolate any history reader behind a nonexported archival module without HTTP/P2P/public generated projections. Do not import legacy rows into canonical Forum sidecar or tally.
2. #777 financial owner with #780: retain one private legacy outbox decoder/reconciler with original raw transactions, exact frozen policy/chain, lease generation and terminal recovery identities. Permit only original pending status transitions and bounded terminal recovery accepted by its owner. Admission of fresh protobuf requests must be separately retired. Recipient recovery that returns old bytes over HTTP is network exposure, so it cannot be called private archival until an accepted exact successor/import path removes it.
3. #797 presentation/RPC owners: after fresh network/profile and auth successors are accepted, preserve exact old profile/metadata bytes through a narrowly private inspector if product support requires it. No get_pubkey fallback for fresh authentication, sniff-based public fetch, discovery page or peer push may survive as archival.
4. #797 Lotus owner: preserve burn markers, wrappers and original authority before any public caller removal. Public legacy history federation is active exposure, not exempt archive. Needed replacement/support decision precedes isolation; no broad database rewrite or drop.
5. Only after those closures, narrow generated bindings to exact private readers. Extract/preserve cashweb-payload chain_adapter and other noncodec APIs; public prost SignedPayload and cashweb-http-utils protobuf/error exports remain active elsewhere today. Consumer-zero and actual Node/browser bundle/dependency proof must precede generator/prost removal.

Required bounded proofs, later under owned leases:
- Real predecessor-created DB/Level rows (not current encoder round trips): native outbox versions1/2/3, digest-only ambiguous attempts, delivered ownership predecessor, protobuf and CBOR legacy profiles, topic predecessor absent/explicit formats and legacy stored field omissions. Open, close, reopen without changing exact financial bytes; characterize already-existing migration writes separately.
- Old→new→old reopening/rollback compatibility on copies with pending and terminal records. Prove original caller can still reconcile policy/chain/raw bytes and indexes after new reader use, or explicitly freeze the narrower accepted rollback support boundary. Do not downgrade a live DB or infer backwards compatibility from successful new read.
- Crash cuts before/after durable request/lease, submitted-unknown/nonce ambiguity, confirmed-prefix, terminal-before-cleanup, recipient import-before-ACK and history compaction. No fresh spend, re-sign, lease release or silent data discard on corrupt/missing mismatch; exact held reservations survive restart.
- Negative source/export plus actual route tests: archival bytes never returned by normal HTTP/P2P/discovery/status, no profile-row fresh auth, no format sniff fallback; both relays and browser/Node bundles cannot import a generated archival transport facade. Private archival calls must be demonstrably finite and bound.
