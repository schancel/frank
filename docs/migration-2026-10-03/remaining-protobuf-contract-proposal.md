## Proposed dependency order and finite packets

1. **Presentation consumer contract and cutover.** Freeze one profile data model using the existing schema3 allocation, with explicit current-account association that grants no routing/RPC authority. Owner accepts exact collection/search page/cursor/ACK/error shapes before dispatch. Bound files to Monad profile HTTP/store verification seams, wallet identity API, and enumerated app/bot presentation callers; name exclusions from DM and Forum. Change complete normal writer/reader/list/search and generated projections together. Gates: real registration→search/discovery→AddContact/contact refresh, all bot marker/no-self/no-bot/denylist rules, discovery progress and faucet exactly-once/funding caps; exact CBOR bytes; malformed/media/sniff/legacy request rejection; browser CORS/errors; restart and old-row isolation. Do not remove assertions to keep the demo green.

2. **Fresh RPC authority cutover, dependent on reviewed #774 and explicit operator provisioning.** Before code, freeze all request-signing callers and their account-to-principal mapping. Reuse the public current-admission facade and existing challenge/capability transcript allocations; no new crypto constant, identity-DH use or address-derived anchor. Owner decides whether already-issued capabilities remain valid for their original TTL or require directory-generation/revocation checks; preserving behavior is not automatically an accepted revocation policy. Gates: EVM JSON-RPC/websocket plus every Bitcoin authenticated operation; unknown/missing/stale/quarantined/corrupt/rollback principal, wrong network/P/tuple, clock and reload races; capability issuance/reuse/expiry/replay; normal demo funding and ambiguous broadcast preservation. Remove fresh authorization reads of archival profiles only after this consumer works. This packet can proceed alongside presentation design; profile storage cannot become archival before it lands.

3. **Lotus metadata federation contract, then replacement.** Owner first specifies supported public metadata/identity semantics, peer admission and inventory/cursor contract, duplicate/conflict behavior, bounded retry/history and the required two-node startup/restart flow. Reuse type2 evidence only where its accepted semantics fit; presentation and private directory authority must remain distinct. Scope HTTP metadata, Registry public API, p2p peer/peers/public_store, daemon initial-download wiring and actual TS producers. Gates: two real relays, initial download, live push, offline recovery, duplicates/conflicts, restart/cursor boundaries and limits; exact bytes; private profiles/mailbox exclusions; wrong peer/anchor/network rejection. Remove metadata protobuf routes/push/pull/startup after equivalent required behavior exists. Stopping peer startup alone fails acceptance.

4. **Lotus public broadcast disposition, separate from metadata and #770.** Freeze support versus explicit retirement and exact burn/payment/update obligations. If supported, obtain independently reviewed allocation covering those obligations before implementation. If retired, owner acceptance must name lost public features, normal callers to remove, and surviving pending-obligation recovery. Either branch must preserve original transactions/bytes and forbid re-sign/reset/replay. Gates include two-node propagation/restart/duplicate/failure and economic authority; do not substitute a Forum parser round trip.

5. **Complete Bitcoin indexer successor contract.** Freeze a coverage matrix from `chronik_policy` and direct SDK uses before choosing transport. Anonymous: blockchain-info, chronik-info, tx lookup; script history/confirmed/unconfirmed/UTXOs; batch UTXOs/summary. Authenticated additionally: block/header/transactions/ranges, raw-tx, global unconfirmed, token/token-ID history and UTXOs, LOKAD-ID history, plugin groups/history/UTXOs, validate-tx; bounded single/batch broadcast. Include Lotus script subscription and validateUtxos calls from lotus-adapter.ts and eCash endpoint/checkpoint verification. Owner must choose a complete existing non-protobuf service/API or separately review an exact adapter/allocation; neither option is selected here. Explicitly decide whether any third-party protobuf remains internally, and reconcile that with #797's no-active-codec goal rather than implying an upstream exemption. Gates: every retained operation, batch/query quotas, auth and capabilities, ingress/response permits, chain/genesis/checkpoint mismatch, endpoint privacy, sanitization, uncertain broadcast, websocket disconnect/reconnect/restart, wallet sync/send and Bitcoin-family demo paths. Balance/send-only proof is insufficient.

6. **Historical reader isolation and pending-obligation ownership.** Prepare per-store disposition before shared codec removal. For each metadata/topics/profiles/messages/outbox store, name exact remaining callers, byte formats, corruption behavior, write authority, public visibility and closure owner. Existing rows/CF descriptors remain intact. Private historical reads grant no fresh auth/routing, emit no network protobuf and accept no new normal protobuf writes. Original pending DM/payment/topic reconciliation remains with #780/#770 and its durable owners; required status changes are not permission to alter/re-sign an old transaction. Preserve account legacy identification, BIP39 recovery UX, wallet pending/attempt stores and faucet/blackjack/Qwen/vendor/raffle settlement/refund state. Gates: old populated/unused DB predecessor reopening and rollback, missing/corrupt headers, exact pending recovery across restart, no fresh authorization from archival rows and no exposed archival endpoints. Retention duration/removal policy must be chosen by owner, not invented here.

7. **Per-family shared export/build cleanup, then final integration proof.** Dependencies: packets1–6 plus #770 and #780's complete normal caller/removal stages, including #782/#784/#785 demo owners. Freeze a zero-consumer list before deleting each generated TS .js/.d.ts pair, Rust proto facade/generator, media wrapper or manifest dependency. Extract/preserve required chain-adapter and validation behavior rather than wholesale deleting crates. BIP70/exported stale RelayClient surfaces require explicit support disposition. Update protobuf inventory from actual reachability, not historical-reader labels. Remove protoc/prost/google-protobuf dependencies only after retained-reader/build requirements are resolved.

Final exact-main gates: route registration + daemon startup + package export/dependency + actual Node/browser bundle audit; captured canonical positive traffic and protobuf/mixed-media negative requests including error paths; two relays and every supported current persona; faucet/raffle/vendor/topic/browser-CORS regressions and pending-economic recovery. Independent protocol/security/economic/persistence/shape review at the frozen integrated tip. No full #797 completion from this proposal or component-only tests.
