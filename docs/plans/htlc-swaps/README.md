# Plan: rebuild Frank atomic swaps on HTLCs (xec-testnet ↔ monad-testnet)

Owner-approved 2026-11-17: rebuild on HTLC (testnet only), fix GenericHTLC edge cases, redeploy once. PR 0 (fix/atomic-swap-records-and-locks) already landed as #2059.

## Protocol shape
A = offerer, XEC depositor, secret holder. A locks XEC first (long deadline T_A); B locks MON second (short deadline T_B). A claims MON (reveals preimage); B reads the preimage from chain and claims XEC. No coordination messages after accept: both compute lock identities from the signed terms (XEC: P2SH script hash; EVM: lockId from sender+terms) and find locks on chain.

## Ownership
- Preimage (A): custody; deterministic `swapPreimage(swapId)` on the canonical role owner beside `conversationIdSalt` (packages/wallet/evm-wallet-material.ts): HKDF from messaging root, label `frank/swap-htlc-preimage/v1`, info = policy name ‖ swapId. Never stored. Explicit new derivation (AGENTS §6).
- Per-swap XEC keys (A refund key, B claim key): EcashWallet custody, derived from XEC account root under `frank/xec-htlc-key/v1`, info = chainIdentifier ‖ swapId ‖ role. New methods `htlcPublicKey(swapId, role)`, `signHtlcSpend(...)`. Keys never leave the wallet. Explicit new derivation.
- XEC funding tx/reservation/exposure: EcashWallet native-operation ledger, operationId `swap:<swapId>:xec-lock` (prepareNativeOperation / recordNativeOperationExposure / submitNativeOperation; p2sh cashaddr recipient).
- EVM lock/withdraw/refund: EVM native-operation journal via `sendContractCall`; new `EvmContractCallRecord` `{kind:'htlc', action:'lock'|'withdraw'|'refund', swapId, lockId}` (update journal validator + sync dispatcher together).
- Signed XEC HTLC spend (claim/refund): swap record, write-ahead before broadcast; deterministic bytes (fixed fee, own primary address, deterministic sigs) so two devices produce the same txid.
- Terms/hash lock/keys/deadlines: negotiation journal (signed events); swap record binds termsHash only.
- Lock state, reveal, finality, outcome: the chain, re-derived each tick, never persisted as authority.
- Timers/watching/auto claim+refund: headless `HtlcSwapRunner` in @frank/swap-protocol, started by app composition at session activation (`startSwapExecution` hook in app/src/utils/identity-session.ts), ticks ~15 s + wallet block events, independent of any card.
- Presentation: SignedNegotiationCard.vue reads the runner snapshot; only issues `authorizeFunding(swapId)`.

Dependency direction: @frank/swap-protocol depends only on @frank/codec, @noble/hashes and its own capability interfaces (XecHtlcCapability, EvmHtlcCapability, SwapSecretCapability, Clock); never imports @frank/wallet (check-deps enforces). @frank/wallet owns the eCash script/tx construction (packages/wallet/ecash-htlc.ts) and EVM HTLC calldata/readers (rewritten packages/wallet/swap-escrow.ts). app composes wallet handles + Chronik (relay proxy /chain-rpc/xec-testnet/chronik). Offer carries the HTLC address; runner checks it equals DEPLOYMENTS[evmChain].contracts.GenericHTLC.address for testnet policy; injected for regtest policy.

## Contract (GenericHTLC v2, one redeploy)
```
struct Lock { address sender; address recipient; address refundAddress; address token;
              bytes32 hashLock; uint256 amount; uint64 expiresAt; uint8 state; /*0 none,1 open,2 withdrawn,3 refunded*/ bytes32 preimage; }
mapping(bytes32 => Lock) public locks;
mapping(address => mapping(address => uint256)) public owed;
function lockIdOf(address sender, address recipient, address refundAddress, address token, uint256 amount, bytes32 hashLock, uint64 expiresAt) public pure returns (bytes32) // keccak256(abi.encode(all seven))
function lock(address recipient, address refundAddress, address token, uint256 amount, bytes32 hashLock, uint64 expiresAt) external payable returns (bytes32 lockId)
function withdraw(bytes32 lockId, bytes32 preimage) external
function refund(bytes32 lockId) external
function batchWithdraw(bytes32[] calldata lockIds, bytes32 preimage) external
function batchDistribute(bytes32[] calldata lockIds, Payout[] calldata payouts, bytes32 preimage) external // recipient-only
function claimOwed(address token) external
```
- lockId bound to msg.sender + all terms (no squatting); duplicate reverts LockAlreadyExists.
- Absolute deadline: block.timestamp < expiresAt ≤ block.timestamp + 30 days. withdraw requires < expiresAt; refund requires ≥ expiresAt.
- sha256 only, bytes32 preimage, sha256(abi.encodePacked(preimage)) == hashLock; preimage stored in locks[id].preimage; keep Withdrawn(lockId, recipient, bytes32 preimage). Remove keccak support.
- All payouts via `_pay`: failed native call or token transfer credits owed[to][token] + emits PaymentDeferred; claimOwed pays msg.sender. All entry points nonReentrant.
- Fee-on-transfer: refuse (balance delta must equal amount, else UnsupportedToken). Native requires msg.value == amount; token path msg.value == 0.
- Remove old overloads, lockWithPermit, and refundAddress==0 defaulting (explicit non-zero).
- Redeploy via CREATE2 scripts/deploy.ts (existing salt; new initcode → new address), then scripts/htlc-round.ts (new ABI) on monad-testnet as proof.
- Other users: game-escrow.ts encodes batchDistribute (switch to bytes32 preimage); poker/liars-dice table escrow: see Follow-ups. Solana generic-htlc untouched (follow-up).

## Deadline rules (policy constants per chain)
testnet: M_evm = 600 s (final = read at latest−10 blocks or `finalized` tag if Monad supports it); M_xec = 3 h (final = Chronik isFinal/Avalanche); S_xec = 2 h MTP skew; W = 1 h watcher downtime.
R1 T_A − T_B ≥ M_xec + S_xec + W = 6 h. R2 T_B − E ≥ 8 h. R3 T_A − E ≤ 72 h. UI defaults E = now+1h, T_B = E+12h, T_A = T_B+12h.
Cutoffs (runner re-checks before acting): A funds XEC only if now ≤ T_B − 6h; B locks MON only if A's XEC output is final with exact script+value and now ≤ T_B − 2h; A withdraws only if now ≤ T_B − M_evm; B claims XEC whenever it knows s and output unspent; B refunds MON once block.timestamp ≥ T_B and lock open; A refunds XEC once MTP(tip) > T_A, output unspent, and A has no landed MON withdraw.
regtest-proof policy: same formulas, margins in seconds (M_evm 5, M_xec 30, S 0, W 10); tests move time with setmocktime / evm_increaseTime.

## eCash HTLC script (P2SH)
```
OP_IF
  OP_SIZE <0x20> OP_EQUALVERIFY OP_SHA256 <hashLock:32> OP_EQUALVERIFY <B.xecClaimPublicKey:33>
OP_ELSE
  <T_A minimal scriptnum ≥500000000> OP_CHECKLOCKTIMEVERIFY OP_DROP <A.xecRefundPublicKey:33>
OP_ENDIF OP_CHECKSIG
```
Claim scriptSig `<sig‖0x41> <preimage32> OP_1 <redeem>`, nLockTime 0, sequence 0xffffffff. Refund scriptSig `<sig‖0x41> OP_0 <redeem>`, nLockTime T_A, sequence 0xfffffffe. SIGHASH_ALL|FORKID, deterministic signatures. Funding output value = xecPrincipal + XEC_HTLC_SPEND_FEE_SATS (1000), A pays. Spends: 1 input, 1 output of exactly xecPrincipal to spender's primary address, fee exactly 1000 sats. B checks one unspent output at hash160(redeem) with exactly that value, final. Reveal: chronik.tx(fundingTxid).outputs[vout].spentBy → spending input script push #2. Tools: ecash-lib 4.14.1 (Script, TxBuilder custom signatory), @frank/nakamoto; prior art packages/bot/demo/regtest/cltv-consensus-fixture.ts.

## State machines
A: offered → (no accept by E) expired. accepted → the XEC lock is automatic when the accept arrives (no Lock button; the signed offer is A's funding authorization); precheck cutoff and no output already at the HTLC script, warn (never block) if the EVM main account lacks gas for the withdraw → persist authorization + operationId, prepare/expose/submit → xecLockPending (wallet re-submits same bytes) → xecLocked(final) → wait for locks(lockIdOf(B…)): final and now ≤ T_B−600 → claiming (read state first, skip if withdrawn) → Withdrawn → claimed (terminal; A never refunds after a landed withdraw). Otherwise → awaitRefund → MTP > T_A and unspent → build refund, persist raw tx, broadcast/re-broadcast → refunded. If B spends with s → claimedByPeer.
B: offerReceived → validate R1–R3 + contract address → Accept (sends accept, persists fundingAuthorizedAt) → awaitXecLock → exact output final and now ≤ T_B−2h → locking (read locks(id) first; LockAlreadyExists counts as locked) | cutoff passes → abandoned. evmLocked → state withdrawn → read preimage → claimingXec (build, persist, broadcast until final) → complete; if A refunded first → lostToRefund. block.timestamp ≥ T_B and open → refunding → refunded. Afterwards claimOwed if owed > 0.
Restart/multi-device: re-derive every state from journal + record + chain each tick; every action reads chain first. Only the account's active device acts (the others observe), so two devices of A do not both fund; a second exact funding output is still reported (`xec-double-funded`).

## PR 1 notes (as landed)
- Contract details the plan left open: `State` is a Solidity enum (ABI `uint8`); `MAX_LOCK_DURATION` (30 days) and `PAYMENT_GAS` (100 000) are public constants. Native payouts inside withdraw/refund/batches forward `PAYMENT_GAS` and copy no return data, so a destination that refuses, needs more gas or burns it is deferred to `owed` instead of blocking the other party; `claimOwed(token, to)` (the only claim function) pays the caller's whole credit to `to` (non-zero; the caller itself, or elsewhere for a contract that cannot take the asset), zeroing it first, forwarding all gas and reverting (keeping the credit) if the payment fails. Token payouts are deferred when the token reverts or returns false. New errors: `InvalidExpiry`, `InvalidValue` (msg.value rules), `UnsupportedToken` (fee-on-transfer, or a token address without code), `NothingOwed`, `ReentrantCall`; new event `OwedClaimed(creditor, token, to, amount)`. `Withdrawn(lockId, recipient, preimage)` is emitted per lock by every withdraw path: `withdraw`, `batchWithdraw` and `batchDistribute` (which also emits `BatchDistributed`). `batchWithdraw` stays callable by anyone (pays each lock's recipient); `batchDistribute` stays recipient-only.
- The wallet encoder (`encodeHtlcLock`) additionally refuses `refundAddress == recipient`; the contract permits it (htlc-round pays itself), so `htlcLockId` and `decodeHtlcLock`/`readHtlcLock` accept such locks. The decoder also checks that a withdrawn lock's preimage hashes to its hash lock.
- Removed from `packages/wallet/swap-escrow.ts` with no remaining callers: `deriveSwapSecret`, `evaluateSwapStepPhase`, `SwapStepPhase`, `to32ByteHash`/`toBytes32Hex` (the Solana builders now take exactly 32 bytes, never hashing text into shape).
- Until PR 2 redeploys, `deployments/monad-testnet.json` still names the v1 contract while the artifact and wallet ABI are v2: nothing may call it in between (no live caller does; `app/src/composables/useSwapEscrow.ts`, the only reader, was deleted in PR 1 as planned in §Deletions).

The `swapId` of a v2 offer must be generated by A itself, preferably deterministically from A's account material and the offer facts (AGENTS §5, e.g. a keyed hash under a private account salt), and `SwapSecretCapability.swapPreimage` must only be asked for swapIds A created. A swapId supplied by a peer, or an old swapId reused for a new offer, would make A publish (by withdrawing) or reuse the secret of a swap that may still be open.

Warnings: `claim-gas-low` (precheck plus warning only, per the ruling), `xec-double-funded`, `xec-foreign-output` (an output at the script that A's lock operation did not make: A does not fund on top of it). A reverted EVM call is retried at most twice (`HTLC_CALL_MAX_REVERTS`); `claimOwed` runs when the contract owes the account, backed off 600 s.
- Runner (`htlc-swap-runner.ts`): `HtlcSwapRunner.tick()` (serialized; `start`/`poke`/`stop`, `subscribe`, `snapshot`) reads each accepted negotiation, validates the terms against this device (chains match the policy, contract equals `evm.htlcContract()`, A's refund key/recipient/hash lock or B's claim key/sender are its own), observes both chains, and performs the one action. Write-ahead: `fundingAuthorizedAt` and `xecLockOperationId` are written before `xec.fund`; the signed XEC spend (`xecSpend {branch, rawTx, txid}`) is written before broadcast and later ticks re-broadcast those same bytes. Funding resumes the existing `swap:<swapId>:xec-lock` operation (exposed/submitted/confirmed is resumed without re-checking the cutoff; a released one ends the swap as abandoned; a prepared one past the cutoff is released). A's withdraw uses its own derived preimage, zeroed after use; B's claim uses the preimage read from `locks(id)` and checks it hashes to the hash lock.
- Active device: `isActiveDevice` (default true) gates every action; inactive devices only observe. With one active device and the deterministic operation id, two devices of A cannot both fund (it replaces the plan's accepted double-funding gap).
- Record (`frank-swap-htlc-v1-<ns>`, `storage/htlc-swap-browser.ts`, revision CAS under a Web Lock as the negotiation store): `HtlcSwapRecord v1 {swapId, conversationId, owner, role, termsHash, fundingAuthorizedAt?, xecLockOperationId?, xecSpend?}`, strict parse, canonical serialization. Deviation: the plan's `evmLockOperationId`/`evmWithdrawOperationId`/`evmRefundOperationId` are not stored. The EVM native journal's `htlc` contract-call record already owns those facts; the capability reads them back with `ownCalls(swapId)`. There is one owner per fact.
- Sync dispatcher not extended: the runner needs no wallet state from `htlc-record` notes. Lock identities come from the terms and the chain, and a device without a record continues from its journal and the chains (shown by the two-device scenario). `htlc-record` still has no consumer.
- Wallet capabilities (`packages/wallet/swap/htlc-swap-capabilities.ts`): `createXecHtlcSwapCapability` (Chronik p2sh history of the HTLC script, MTP from the last 11 blocks, spend branch from the revealed input, funding through the native operation path, `confirmations` or `avalanche` finality) and `createEvmHtlcSwapCapability` (locks at latest and latest − depth, owed/balance/call cost, `ownCalls` from the native journal, lock/withdraw/refund through `sendContractCall` with the `htlc` record, deadline expiresAt − 1 for lock and withdraw).
- Tests:
  - `htlc-swap.jest.test.ts`: 73 table tests covering every A and B transition and cutoff boundary, the testnet and regtest cutoffs, authorship and the record format.
  - `htlc-swap-runner.jest.test.ts`: 7 tests at the capability seam. They cover the write-ahead order, that no secret is asked for a non-derived swapId, the claim being persisted before broadcast, a bad contract or sender, an inactive device and a mismatched record.
  - Browser suite in real Chrome (`yarn --cwd packages/swap-protocol test:htlc-swap-browser`, also part of `test:storage-browser`): CAS, a four-page race with exactly one winner, relaunch persistence and namespace isolation.
  - Two-party integration on xec-regtest and anvil (`yarn --cwd packages/bot regtest:htlc-swap`; jest wrapper `demo/regtest/htlc-swap.regtest.jest.test.ts`, NOT RUN without bitcoind/anvil). Each device is a process of its own (`htlc-swap.device.ts`) with real wallets. Only the EVM RPC URL is redirected to anvil (`anvil-rpc-redirect.ts`, the livecheck equivalent of PR 4's jest.mock). Time moves with setmocktime and evm_setNextBlockTimestamp. Scenarios:
    - Happy path with wallets reopened and a fresh runner before every tick. It includes a stop after A's authorization is written and a stop after B's claim is written, and ends with exactly one funding, one Locked, one Withdrawn and one claim with the persisted txid.
    - B never locks → B abandons, and A refunds only once MTP > T_A.
    - A never claims → both refund.
    - B offline past T_A → A's runner never refunds after its withdraw. A refund made outside the runner leaves B lostToRefund.

## Follow-ups
- Table escrow (owner design 2026-11-18), as landed on the poker and liars-dice bots (still parked, not registered):
  - Preimage: explicit new derivation `frank/table-htlc-preimage/v1` (`packages/wallet/table-preimage.ts`, pinned vectors in `table-preimage.jest.test.ts`, checked against an independent HKDF): `prk = HKDF-Extract(SHA-256, salt = utf8(label), ikm = messaging root)` (whole 64-byte seed for a historical BIP39 account), `preimage = HKDF-Expand(prk, u8(len(game)) ‖ utf8(game) ‖ tableId(16), 32)`. `MonadCanonicalRoleOwner.tablePreimage({game, tableId})`; hosts get `tableSecretCapabilityOf(wallet)` (`chain/evm-chain.ts`), a `TableSecretCapability` that returns preimages only. Bots receive it as `BotContext.tableSecrets`, beside `BotContext.contractCalls` (the wallet's `sendContractCall`/`resumeNativeOperation` and its main account; `packages/bot-framework/src/contract-calls.ts`). The table id is 16 bytes the bot draws itself; the bot derives preimages only for tables it opened and kept.
  - Terms (`packages/wallet/table-escrow.ts`, headless, used by bot and player): recipient = the bot wallet's main account (only the recipient may `batchDistribute`), refundAddress = sender = the player's main account, amount = buy-in, native token, hashLock = sha256(table preimage), expiresAt = table start + 24 h (the same for every lock at the table).
  - Wire: the poker (keys 19/20) and liars-dice (keys 23/24) items gain `escrow {arbiter, hashLock, expiresAt}` (the bot's table items) and `buyInLock {lockId, account, signature}` (a player's `join` only; on any other action the item is malformed). `signature` is `account`'s EIP-191 signature over `frank/table-join/v1` (`packages/wallet/table-join.ts`, pinned vectors in `table-join.jest.test.ts`): keccak256(abi.encode(domain, chainIdentifier, contract, game, bytes16 tableId, bytes32 lockId, address joiner)), joiner = the identity address the join comes from. Hosts sign through `tableJoinSignerOf(wallet)` (`chain/evm-chain.ts`), a `TableJoinSigner` that signs only this. Shared codec `message-item-plugins/shared/table-escrow-fields.ts`; golden bytes and malformed cases in its test.
  - Seating: the bot checks the join's signature for the sender's identity (another identity naming a lock seen on chain is refused), recomputes the lock id from the table's terms and `account`, reads `locks(lockId)` and seats only an open lock with exactly those terms whose deadline is at least 1 h away; one seat per lock and per player. A text join is refused. Seats, settlements and recovery steps of one table run one at a time (a lane per table in `TableEscrows`, the record read again after each wait); the game's own join runs inside the seating step, so a player the game refuses holds no seat and is told so.
  - Settlement: the bot writes the payouts into its state store (`table-escrow:<tableId>`), then sends `batchDistribute` with the derived preimage through `sendContractCall` with a new sibling record `EvmTableHtlcCallRecord {kind:'table-htlc', action:'lock'|'refund'|'distribute', game, tableId, lockIds}` (journal validator and consolidator check against `htlcTableCallOf`). Payouts go to each player's locking account: poker splits the pot by chip stack after the hand (one escrowed hand per table, then the table is closed), liars-dice pays the winner the pot. Every end of a game settles, a turn timeout's auto-fold or auto-challenge included; a showdown that fails verification returns every buy-in. The distribute is sent with the locks' deadline and its operation id is written down from `onSigned`, before it is handed out; a send that fails is retried in the background, as written, with backoff (5 s doubling to 10 min). After a restart (`onStart` → `TableEscrows.recover`) a kept table is settled as written (a handed-out call is resumed, a reverted one (receipt status 0) re-sent with the same payouts), or, with nothing written, its buy-ins are returned; a table whose locks are all withdrawn or refunded is dropped. Recovery runs per table without blocking startup; a table that fails is logged and retried with the same backoff.
  - Player: `lockTableBuyIn` and, from the deadline on, `refundTableBuyIn` (refuses a lock that is not open, not past its deadline, or not this wallet's) through the player's `sendContractCall` with `table-htlc` records.
  - Evidence: `packages/bot/src/bots/table-htlc.anvil.jest.test.ts` (real wallets on anvil as monad-regtest: lock, seat, wrong/missing lock not seated, payout, refund after expiry, restart re-derives and settles both ways, a refunded table forgotten, front-running joins refused, concurrent joins, a join the game refuses, turn-timeout settlement for both games, background retry of a failed send, a failing table's recovery not blocking startup or other tables).
  - Open: the app has no join that locks (the poker/liars-dice cards are not mounted and send a text `/poker join`); a `table-htlc` call has no note-to-self record item (its note carries only the wallet-sync item), so another device of a player does not learn its lock id; a successful distribute that leaves locks open, and a reverted one, are handled by reading the receipt but not exercised on chain; seating reads `latest`, not a finalized block.
