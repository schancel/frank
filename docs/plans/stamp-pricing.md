# Dynamic default stamp pricing

The recipient receives a fixed target of 0.1 AVU, bounded below by the selected adapter's live minimum paid stamp. Network fees are separate. This is a fixed energy-value policy, calibrated near one US cent once; it is not a dollar peg recomputed on refresh.

Current ownership: chain configuration supplies a fixed raw default; the app stores optional explicit raw amounts per conversation; the wallet enforces its live paid-stamp floor; bots cap replies by confirmed incoming value. Target ownership: one pure shared AVU policy owns the default decision, host composition supplies public configuration and observed rates, family adapters own fees, and custody receives raw amounts. The public override is `FRANK_DM_DEFAULT_STAMP_AVU` (`QCLI_` prefix in the browser), default 0.1.

The amount is max(ceil(targetAvu / avuPerCoin \* baseUnitsPerCoin), minimumStamp). Conversion uses decimal rational integers and rounds upward. Unsupported messaging, absent/stale conversion rates, and unavailable fees remain explicit. Zero and explicit conversation amounts bypass dynamic default calculation; updates never overwrite them. The existing raw amount wire and persistence formats remain unchanged.

Composition will inject a narrow asynchronous default resolver into messaging. The SDK resolves it only for omitted stamp amounts. The app shows the same default quote and distinguishes an explicit reset from entering an amount equal to the current default. Bots share the policy while retaining min(confirmed incoming value, configured ceiling), free replies, and named settlement amounts. The old 0.01 MON blackjack minimum wager must become independent before stamp defaults change. No geometric distribution, topic pricing, chain selector, Solana messaging enablement, or general UI cleanup is included.

Before shared wallet edits, agree the resolver API with the coordinator and native-transfer worker. Before bot-host edits, integrate the payment-credit predecessor. Tests cover upward conversion at 18/9/2 decimals, fee-floor dominance, absent/stale/unsupported observations, free and explicit amounts, and shared host/default send behavior. Production proof must use actual oracle data and the real relay/chain; a missing MON rate must not be replaced with a fabricated quote. All tests and builds require the coordinator's exclusive machine slot.

Follow-up outside this demo: Tempo's registry presentation uses USD/tUSD and the oracle's `ASSET_DECIMALS.tempo` is 6, while `createEvmChain.fromDisplayAmount` currently parses 18-decimal ether. Dynamic defaults explicitly refuse that unit mismatch. A custom/token transaction builder also needs an authoritative priced transfer-asset identity before it can use this native-coin policy; equal decimals alone are insufficient. No Tempo custody/unit rewrite is included.

The captured contact stamp is a durable authorization fact in the existing payment journal's `stampValueWei` field. New contact plans always populate it before signing; the prepared result returns it to the host. Conversation metadata remains only an optional explicit user choice and never owns a computed default. Reconciliation reads the captured amount without a quote. A legacy unfinished contact record missing that fact fails visibly before mutation; it is never silently repriced, migrated or deleted.
