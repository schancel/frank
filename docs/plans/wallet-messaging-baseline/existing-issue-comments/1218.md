This remains the home for atomic inventory persistence and historical archiving; the wallet/messaging baseline plan should not create a duplicate storage ticket.

Before implementation, map the durable owners of operation reservations, signed requests, links, and active inventory. The planned input-reservations item defines view ownership and private provisional state; its accepted contract must precede storage changes to those records. Separate atomic correctness from optional archival optimization so recovery is not blocked by an archival redesign. Existing canonical journals may remain authoritative where appropriate.

Acceptance additions proposed for owner review: interruption at each relevant commit boundary preserves input ownership and exact original-operation recovery; restart never exposes an uncertain operation's inputs as free; archiving cannot delete evidence needed to reconcile partial or delayed relay/recipient broadcast. Storage faults must remain observable. No migration framework for obsolete development data and no implicit deletion of custody.

This is a proposal, not a claim or assertion that the work is absent from current main. Recheck implementation and active ownership before dispatch.
