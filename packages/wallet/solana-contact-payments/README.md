# Experimental Solana payment owner

This uncomposed successor supports native SOL and classic SPL, received-descriptor import and respend, and gathering from independent source accounts. It is absent from wallet/app exports and does not enable a chain capability. Crypto/protocol acceptance remains separate. Public construction predecessor is `3de76bb6`; custody predecessors are sender `98084a6d`, explicit ATA rent `4cbd3e46`, and closed restored-recipient signing `12fae3de`. The Edwards proposal and independent vectors remain experimental.

## Ownership and persistence

`SolanaPaymentState` owns public positions, reservations, immutable operation intent, the unsigned random contexts and destination, original signed transaction set, envelope digest, and finalized outcomes. The single `format:4` snapshot also retains account retirement slots: repeated old receipt/sync observations cannot resurrect spent positions. No seed, scalar, nonce prefix, or encrypted message is persisted here. Generic messaging alone owns its encrypted envelope. Trusted composition invokes `expose(operationId,{payloadDigest})` only after its generic `onEnvelopeDurable` callback. The digest never participates in key derivation.

`IndexedDbSolanaPaymentPersistence` owns atomic strict-durability read/modify/write transactions across handles and tabs. A read-only open of an absent namespace aborts creation. The first authorized mutation initializes it. Missing state is inspectable without writing defaults; unsupported, corrupt, or foreign state rejects without reset. No old-format reader or migration exists, including the experimental format-1, format-2 and format-3 predecessors. For an unfunded disposable development environment, the host may explicitly choose a fresh namespace; there is no implicit deletion or reset of funded state.

`quoteReview(request)` accepts operation UUID, canonical chain, recipient spend point, full selected asset, amount and explicit destination-ATA creation permission. It accepts no caller-invented fee budget. A public fixed estimation-only message obtains actual RPC planning fees; the existing operation map persists a `quoting` record with immutable allocation/source proposals and distinct random `cryptoOperationId32` and `derivationContext32` **before** custody derivation. No separate draft owner/map exists. An interrupted derivation or unavailable/mismatched exact quote retains that draft and its contexts without reservation, signing or exposure. The WASM adapter deterministically reproduces public destinations after reopen. The private scalar remains inside WASM. Classic token decimals are signing metadata; they do not change the frozen Edwards transcript.

The final exact unsigned message is constructed by the separately frozen public-only fixed builder and queried through canonical RPC. A planning/final fee mismatch rejects visibly before review completion. One atomic commit replaces the draft with a complete `quoted` operation. Only complete operations cross the public review boundary. Each member owns exact fee/rent/native-debit ceilings and unsigned-message/lifetime evidence; aggregate ceilings equal their sums. Native debit includes principal; SPL debit excludes the transferred tokens. Destination ATA rent is an explicit construction cost. Recipient native gas funding is absent.

The unsigned quote freezes member allocations summing the full intended amount and exact proposed sources, reserving nothing. The protocol maximum is `MAX_PAYMENT_MEMBERS` (64); a constructor may choose a stricter operational limit. Small accounts are exhausted when feasible; larger usable capacities are reconsidered before member-bound failure. A completed review is immutable and repeated IDs cannot change its intent or ownership. RPC blockhash evidence has an explicit last-valid height, rather than an indefinite validity promise.

Prepare obtains a fresh blockhash only within the same approved operation, contexts, asset, recipient, amount, sources and financial ceilings. It queries the exact fresh unsigned message and current necessary ATA rent **before signing or reservation**, rejecting increased costs. It then reserves the exact proposed source set in one short atomic transaction; unavailable sources reject rather than silently replanning an approved review. Each member has an independent source owner/transaction. Network/custody work takes no inventory lock. SPL reserves its classic ATA and existing same-owner native fee account; no consolidation, separate fee payer or native subsidy is constructed. The backend emits only fixed idempotent classic ATA creation, TransferChecked and memo. Token2022/arbitrary token extensions remain unsupported. Signed message bytes must equal the checked unsigned message.

`primary` and `received` signing references are public tagged records. Received references retain full original B/R, chain/asset, crypto operation/context bytes, member index, original receipt amount and P. Import first asks WASM to validate seed/B affinity and the full original transcript/P, then verifies actual finalized chain effects. Repeated receipt import cannot overwrite a reservation, newer observation or consumed account. Custody resolves the private recipient scalar/prefix lazily inside WASM for a separately bound new outgoing descriptor. Original receipt amount is not treated as current balance. Token receipts retain an explicit `needs-native-gas` prerequisite until an owned native account balance is observed; the sender does not fund it implicitly.

The engine verifies canonical RPC genesis identity from the protocol registry, exact one-transfer transaction policy, standard Ed25519 signature, actual message fee against authorization, and complete original-set atomic persistence before returning bytes. The closed WASM backend owns the exact cryptographic transcript and authorization memo digest; the engine checks the memo program, structure and absence of extra instructions. The injected RPC adapter must faithfully implement initialized-token-account validation, fee lookup and **finalized** evidence semantics. No permissive generic RPC result is silently treated as those facts.

An unsigned interrupted reservation can be explicitly released while retaining contexts/destination. Signed or exposed attempts cannot be released through that path. Submit requires durable envelope binding and rebroadcasts the original bytes. Unknown status, timeout, blockhash expiry or UI discard do not release claims or create a replacement. Finalized execution evidence retires only that member’s source observations. Actual post-transaction source balances are installed atomically with `postSpendSignature` at the finalized slot; the retirement watermark still rejects older/equal receipt replay. Zero balances retire completely. Repeated finality cannot retire a newer observation or release another member. Partial receipt sums include only members with matching successful finalized effects; unknown submissions remain reserved. Failed transactions require consistent finalized error metadata and source balances.

Receipt verification reads successful finalized original bytes and exact native/token recipient balance effects. The verifier itself does not mutate state or rebroadcast. The engine’s `recordIncomingClaim` validates the original signature, fixed instructions and closed recipient custody affinity, then durably retains the authenticated claim with its payload digest before any RPC call. `reconcileIncoming` credits inventory only after matching canonical finalized evidence, atomically with the retained claim outcome. Token receipts explicitly require an owned native balance observation before spending.

## Concrete RPC predecessor contract

The successor adapter owns only projection of explicitly injected Solana JSON-RPC results into the financial owner's narrow RPC contract. It has no inventory, key, message, endpoint-default or planning ownership. Before each financial read or submission it verifies the canonical chain's registry genesis hash. It requests finalized transaction bytes and metadata, exact history signature status, classic initialized mint/account records, fee and plain 165-byte token-account rent. Native RPC numeric quantities must be exact nonnegative integers. The HTTP transport preserves integer tokens as bigints through full u64 validation; already-decoded injected JS numbers must be safe integers and otherwise fail visibly. Token amounts remain canonical decimal u64 strings. Token2022, malformed account layouts, ambiguous finality, signature/byte mismatches, unsupported transaction versions and inconsistent metadata reject. Missing/unknown transactions remain null, preserving original reservations and recovery.

This predecessor adds no persistent or wire format and removes no API. Its only submit path forwards the caller's original bytes as base64. Source and recorded-shape fixture tests cover wrong genesis, unsafe amounts, malformed classic accounts, partial/missing finality, exact original submission and finalized metadata projection; owner interruption/reopen tests remain the ac0e4aa9 acceptance boundary. No live RPC or funded account is accessed by these checks.

These include the concrete adapter through original submission timeout, state/adapter reopen, pending reservation retention, exact rebroadcast and finalized residual installation. The HTTP transport requires an explicit endpoint and fetch implementation, validates JSON-RPC IDs/errors, and uses no default endpoint. Financial account reads additionally reject delegate, close-authority, frozen or native-wrapped token accounts. ## Incoming original evidence contract (format 4)

The existing `SolanaPaymentState` remains the sole owner of incoming evidence and available positions. New `incoming[signature]` records retain the complete original transaction, full public descriptor context/asset/destination/amount, authenticated payload digest and pending/confirmed/failed status. No competing coin store, encrypted envelope or messaging dependency is introduced. Format 4 deliberately rejects earlier experimental snapshots; no migration, reset or key deletion is performed. Read-only restoration verifies original signature and fixed transaction policy but does not initialize custody or contact RPC.

Trusted authenticated mailbox composition calls `recordIncomingClaim(claim,{payloadDigest})` and awaits durability before advancing its frontier. The digest is a host authentication/exposure fact, not a key-derivation input or a wallet assertion of transport authentication. Ingestion performs pure exact original validation and closed WASM recipient-affinity validation without RPC, and creates no spendable funds. Repeating the original is idempotent; changes to context, asset, amount, original bytes or digest reject. Offline and unknown status remain pending. `rebroadcastIncoming(signature)` validates restored custody affinity and sends only the retained original bytes, without signing, replacement, subsidy or expiry-based discard.

`reconcileIncoming(signature)` requires canonical chain identity and matching finalized status, exact original bytes and metadata. Failed execution remains retained with no inventory credit. Successful actual recipient effects and public custody reference enter inventory in the same atomic state commit as claim finality. Existing retirement watermarks and newer/reserved positions remain authoritative; repeated finalized claims do not re-import or resurrect funds. The stored `credit` is the historical import disposition, not a claim that a subsequently spent balance remains available. `incomingProgress(signatures)` reports separate intended and verified received sums for a bounded same-asset member set, including partial outcomes. No caller may infer full receipt from message arrival.

The old finality-first `recordReceipt`/standalone `importReceived` path is removed in this coherent experimental baseline. Acceptance includes offline strict-IndexedDB persistence, custody close/reopen, original-only recipient retry, finalized atomic credit, failure/partial reporting, malformed and cross-chain rejection before durable rows, and receipt replay after spend retirement. Generic mailbox activation and protocol allocation remain gated separately.

## Finalized owned-balance and asset-discovery contract

The read-only RPC successor adds `readOwnedBalances({owner,selectedAsset})`, returning `{finalizedSlot,nativeBalance,assetBalance}`. One finalized `getMultipleAccounts` context binds the native System-owned empty-data account and, for SPL, its classic ATA and initialized mint. Missing native account is observed zero; missing ATA is `null`; an existing eligible zero-balance ATA remains explicit zero. All balances are exact decimal u64 strings. No custody, signing, inventory credit, state writes or presentation defaults are involved.

`discoverClassicAssets(owner)` returns only verified classic ATA mint/program/decimal metadata. It queries the classic program, excludes non-ATAs and unsupported account authorities/states, and rejects malformed or foreign-owner/program responses. Candidate ATAs and mints are re-read in RPC-sized batches (maximum 100 addresses per official `getMultipleAccounts` request); all batches must share one nonnegative safe finalized context at least as recent as discovery. Incoherence rejects the whole result instead of presenting a partial asset list. No USDC table, Token2022 fallback, ticker or configured-presentation ownership is added.

The explicit HTTP transport uses the already installed upstream `@solana/rpc-spec-types` 8.4.0 lossless parser and declares bigint integer encoding. Critical HTTP numeric fields require bigint tokens, preventing decimal forms such as `1.00000000000000000001` or negative exponents from rounding into accepted integers. Exact integer tokens, including exact nonnegative exponent forms supported upstream, retain their full value through u64 validation. The parser's reserved `$n` value-object representation is rejected in raw JSON before parsing. Injected already-decoded transports continue to accept safe numeric integers or exact bigints; unsafe numbers reject. Slots, indices, versions and response IDs convert only within the safe integer range.

Acceptance covers actual HTTP text with values above 2^53 and the u64 maximum, overflow and rounded-fraction rejection, native/SPL missing versus zero balances, wrong ownership/mint/program/decimals/genesis, unsupported account policy, asset discovery filtering, batch-context mismatch and network failures. Host composition alone feeds verified public observations into the existing state owner and applies configured asset presentation. Official method boundaries: [getMultipleAccounts](https://solana.com/docs/rpc/http/getmultipleaccounts) and [getTokenAccountsByOwner](https://solana.com/docs/rpc/http/gettokenaccountsbyowner).

## First classic SPL receipt metadata

`CanonicalSolanaPaymentRpc.readClassicMint({mint,program})` reads one exact mint address in a canonical-genesis-verified finalized `getMultipleAccounts` response and returns `{mint,program,decimals,finalizedSlot}`. It reuses the same strict classic 82-byte initialized-mint/authority/layout parser and lossless HTTP numeric validation as owned balance reads. No recipient ATA or prior asset inventory is required. This allows guarded host composition to resolve an unfamiliar first-receipt mint before constructing its typed receipt claim, without hardcoded presentation metadata or default decimals. Missing, invalid, nonclassic, wrong-chain or unavailable observations reject; no wallet state, key or submission is touched. Durable `recordIncomingClaim` remains RPC-free once its complete authenticated typed claim reaches the owner. Wire formats and experimental activation gates remain unchanged.
