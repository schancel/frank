# Experimental received-source signing prerequisite

Tier 3 successor to 4cbd3e46. Custody reconstructs the original received destination key exclusively from the immutable received descriptor and seed. The financial owner authenticates actual receipts, tracks observed current balances for each asset, reserves inputs and authorized native fee/rent ceilings, journals exact signed bytes and controls exposure/recovery. No application enablement, format migration, new cryptographic derivation, arbitrary-message signer or private-key export is introduced.

The obsolete experimental public `signTransfer(receivedDescriptor, spend)` route is removed from Rust bindings/runtime/types, with no compatibility shim. It lacked the approved outgoing descriptor and spending caps. Native private fixed-Q/signature vectors remain; actual browser recipient proof now exercises the complete closed API. There is no alternate public recipient signing path around outgoing authorization.

`signReceivedTransfer(received: {descriptor, publicKey}, newSenderDescriptor, spend, authorization)` checks canonical chain affinity, source public key equality, complete new outgoing descriptor/R/P/amount/asset/operation/context binding and existing fee/rent/native debit limits. It signs the same closed native/classic SPL builder, with explicit fixed ATA creation when authorized. The signed intent memo additionally binds the complete original received Q and original public key, separate from the new sender Q.

Original Q is recomputed including its original asset/program/amount/context. Its asset derives the private key; it is not a balance record. The new outgoing asset can differ: SOL gas or residual at an SPL-derived address, or a subsequently verified token balance at a native-derived address, remains owned by that address. Never credit an unverified asset or infer current balance from the old receipt amount. The owner checks the selected current asset/ATA balance and full native debit before signing; the backend enforces typed transaction construction and caller-authorized ceilings, not RPC truth.

Existing recipient p/zP, sender HMAC derivation and all Q encodings remain unchanged. Scope.prepare reconstructs the source p/zP and its existing one-shot signer signs the fixed message. Runtime exposes only typed public data and signed outputs; close/abort/wipes retain prior semantics. Public descriptors can restore the signer after reopen; secret material never enters persistence.

`validateReceivedDescriptor(received)` reconstructs the same source capability and immediately drops it without signing, returning only the validated public key. The financial importer calls this before marking an observed source as owned. It performs no RPC, inventory mutation or receipt accounting; actual chain effects still require independent verification.

Evidence must include actual WASM reconstruction from persisted public source descriptors after close/reopen, independently reproduced recipient signatures, real web3 message/ATA parsing, native and cross-asset spends, forged source and outgoing descriptors/caps rejected, and unchanged predecessor vectors. Actual chain receipt import/current inventory/recovery belongs to the dependent financial owner's integration tests. A different reviewer must review the frozen implementation before enablement; vectors are not a formal cryptographic audit.
