# Experimental sender custody contract

Tier 3 prerequisite atop be85afe2. Custody owns private derivation and fixed transfer signing; the financial owner owns authenticated recipient publication, immutable quotes, fee/rent RPC verification, balances, reservations, persistence and exposure. No application capability or protocol allocation changes. Existing recipient Q and zP remain byte-identical.

For a public intent, J is canonical restricted CBOR array8 [SCHEME, canonicalChain, asset, recipient B, cryptoOperationId32, memberIndex u32, noncircular derivationContext32, positive amount u64]. SCHEME and asset encoding are exactly those of existing Q; J omits only R. Context is frozen before R and cannot contain R/P, resulting ciphertext or transaction. Existing sender seed expands normally; its private prefix z keys HMAC-SHA512 over C(["frank:solana-stealth:sender-ephemeral:v1", bstr(J), counter]). Counters are unsigned canonical CBOR 0 through 4095. Interpret first32 digest bytes little-endian, reject unless 0<r<L without reduction/clamping. Compute existing R/D/Q/t/P; zero tweak or identity destination continues counter. Exhaustion fails visibly; no random fallback. r never signs and never becomes a signing prefix. Sender seed compromise reveals these outgoing links. This additional KDF requires independent crypto review under PRF/key-secrecy assumptions; reasoning and vectors are not a formal security proof.

deriveDestination(intent) returns public descriptor including R plus P, reproducibly after reopening. signPrimaryTransfer(descriptor, spend, authorization) recomputes R/P and rejects changed descriptor/destination/chain/asset/amount/operation/context/source. Primary signing preserves the published standard Ed25519 key. Authorization contains exact quoted fee, maximum fee, quoted rent, maximum rent, maximum native debit and explicit ATA-creation choice. Checked arithmetic rejects overflow and excessive spending before signing. These limits enter the signed memo. Solana instructions cannot independently enforce truth of caller-supplied RPC fee/rent quotations; the financial owner must verify current quotes and total funds immediately before signing and before exposing the immutable signed account set.

Core commit permits existing classic SPL ATAs only (createDestinationAta=false, rent=0). The separate dependent ATA commit adds explicit idempotent destination ATA creation with known positive approved rent, as construction expense; no extra SOL payment or recipient subsidy. For creation, maximum native debit reserves maxFee+maxRent, while quoted rent must be positive and <=maxRent. Native creation and nonzero rent without creation are rejected. The builder fixes all six ATA accounts, instruction byte and program; caller instructions cannot enter it. Token-2022, arbitrary instructions/messages, scalar exports, fallback signers and app integration are excluded. Runtime retains close/abort and seed wipe behavior. No persistent format is introduced: public intents/descriptors belong to the following financial owner; quoted R/P must reproduce or fail, never silently replan.

Evidence: independent Python/Noble/OpenSSL sender vectors, real WASM/Chrome primary native/classic SPL signing and parsed transactions, malformed/mutated inputs and economic caps rejected, restart determinism, close/wipe, and unchanged recipient fixtures. Review the frozen candidate with a different crypto reviewer before integration. Delete this isolated experiment if the scheme is rejected; no migration or live funded data is affected.
