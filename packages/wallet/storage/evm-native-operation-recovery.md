# Current recovery of an archived own move

`EvmNativeOperationJournal` owns one signing graph and later current facts for the same operation ID. It never creates another payment or signs during archived recovery.

- `history:<id>` and `completion:<id>` remain immutable, including their original operation digest. Historical `abandoned` observations are retained as the earlier wallet decision; they are not new permission to release exposed bytes.
- An `operation:<id>` row tagged `archived-own-move-current` links the original ID/digest and eligible member indexes/signed hashes. It stores only later observation/account, projection and sync facts. The materialized view uses the original signing graph; a whitelist rejects changes to signatures, exposure, value, nonce, fees, destinations, dependencies, stages or unrelated historical members.
- Eligibility is limited to original signed, exposed, abandoned `change`/`funding` members in a noncancelled transaction set. Missing custody or conflicting current ownership stays observable without replacing another holder. Activation is an authorized mutation, never part of read-only opening.
- `claimed` current authority uses existing native admission and CoinList reservations. `observe-only` authority requires every eligible own nonce already canonically decided and cannot return to pending or replay. Both use exact pre-RPC member CAS, so inclusion/newer facts beat stale observations.
- `recovered:<id>` retains later completed facts and a separate current completion digest. Completing current recovery does not rewrite original history or allocate an operation/preparation ID. `readOperation` resolves current facts; `readArchivedOperation`/`historyPage` remain original evidence. Wallet history prefers current facts and deduplicates by the original ID.

Original source keys remain with their existing custody/inventory owner. A local projection fence retains existing keys across activation storage; uncertain commits retain it until reopening. Target discovery uses the original derivation index and actual configured-head nonce/balance outside source locks. A missing/failed target observation leaves source projection debt, and newer target/source evidence or reservations cannot be overwritten by an old receipt amount.

Existing `consumed:` ownership is reused when safe. A `recovery-consumed:` index is needed only when the old raw consumed a nonce while a newer active operation still needs its own eventual immutable consumed-owner index. It points to completed later evidence and grants no input reservation. Neither owner index overwrites the other; preparation rejects a pair proven consumed by either. The focused collision/completion test covers old recovery completing before the newer operation archives.

Discovery uses bounded immutable history pages, with at most 16 rows and a soft 32-member budget (one larger row is allowed up to the existing 64-member limit). It uses the existing background cooperative yield/input-backoff behavior. Background reads capture the original database handle and open lifetime, enumerate and close a bounded iterator before validation waits, and validate immutable archives outside current mutation serialization. Close invalidates the captured lifetime and rejects a suspended read; it cannot switch to empty ephemeral history. Foreground history remains serialized. This does not cache parsed lifetime history or turn history into another inventory. Financial reconstruction still uses current canonical observations and typed owners.

The frozen historical fixture under `../fixtures/archived-own-move/` came from actual baseline lifecycle exposure, refusal, abandonment and archival. Its signing graph is not regenerated from repaired product behavior. See that fixture's README for capture provenance and the original fail-before gate.
