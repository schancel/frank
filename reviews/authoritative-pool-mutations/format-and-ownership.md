# Authoritative HD pool mutation baseline

The pool store is the sole writer of HD rows, terminal checkpoints and allocation high-water. `mutate` accepts a synchronous reducer over detached committed snapshots, compares every touched row's captured revision, writes one durable batch, and publishes only afterward. Network/signing waits remain outside this short boundary. The pool owns lifecycle construction; input admission owns operation claims; the keyring remains custody's unchanged derivation owner.

Node's Level lock excludes independent physical database openers. Pool wrappers over one opened store share that actual authority. In browsers the existing `runNativeTransactionExclusive` Web Locks capability encloses authoritative LevelJS reload, revision comparison and durable batch across contexts. Missing Web Locks refuses instead of falling back to realm-only coordination. The browser qualification uses actual LevelJS, strict IndexedDB transactions, two independent Chrome pages, and SIGKILL/relaunch of Chrome with the same disposable profile. It does not simulate a successful backend. Node-only filesystem code is mapped to a module that throws if the browser ever executes it.

A failed or ambiguous durable write fences store reads, selection, later mutations and repeated flush. Close drains admitted writes and closes the backend; reopen validates and reads the actual disk outcome. A known stale revision is a no-write refusal and does not poison an otherwise healthy store. Spent/retired rows cannot return to nonterminal state, even when a writer supplies the current revision; terminal evidence may still append and exact replay is idempotent. Lease acquisition holds its pool claim before its first await and returns a handle only after durable `in-use`. Release preserves the live lease until its terminal/unused transition commits.

Pool record and checkpoint envelopes are `{ version: 3, revision, value }`, with positive safe-integer revisions. New rows begin at 1; semantic mutation advances once; identical replay preserves revision; overflow refuses. Terminal conversion advances the same index's revision and atomically removes its row. The `__pool_format__` marker is `sub-account-pool-v3-authoritative`. First authorized mutation writes the marker together with the row/high-water. Read-only opening of a genuinely empty store writes no marker/default rows. Old unversioned rows, missing-marker records and incompatible manifests refuse without conversion, synthetic history, alternate namespaces or deletion.

Wallet manifests now accept only version 3 with `sub-account-pool-v3-authoritative` and the existing `change-pool-v2` intent. Missing-manifest initialization qualifies existing pool state before writing a manifest or generating custody. Existing manifests/keys/signed obligations remain preserved on refusal. There is no automatic reset path: owner disposition is required before release, particularly for funded state. Release remains held. Rolling code back after version 3 writes cannot restore an old reader safely.

This predecessor adds no funding-history collection or partial-preparation hold. The latter is the next authorized design; retained anchored funding evidence subsequently uses manifest 4 and `sub-account-pool-v4-funding-evidence`. Missing-receipt positive-balance eligibility, completed funding artifact loss and incomplete multi-funder ownership remain follow-on work, not claims of this candidate.

Compression removed the old unrestricted store writers rather than retaining a funding-only bypass. The in-memory implementation provides the same mutation semantics; Level extends only coordination, authoritative reload and durable publication. No generic storage framework or separate provenance cache was introduced. Runtime removal assertions and production typechecking enforce the deleted mutation API; source search confirms no old pool owner writes remain.

Interrupted new manifest initialization qualifies each component before binding. The HD marker, root binding and high-water initialization share one batch. An existing version-3 manifest with a genuinely empty missing component may finish its already authorized initialization; nonempty unbound HD/change state refuses. The bundle proves an unbound change component empty through public reads before forwarding its existing initialization option, with no change-store implementation/schema redesign. Tests compare all custody/manifest/pool/change bytes on refusal and manifest/seed bytes across repeated initialization reopen.
