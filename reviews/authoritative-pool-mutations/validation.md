## Semantic test changes beyond await propagation

The old failed-write funding tests asserted that an undurable row remained inspectable and could be rewritten/retried in-session. They are replaced with actual persistent-owner assertions that submission does not occur, reads/retry/flush stay uncertain, and reopen exposes the unchanged unfunded disk row. An exposed, already-durable funding transaction may be rebroadcast identically: no-op revision replay no longer forces an unnecessary physical write merely to establish durability again. The stopped-submit test now requires identical raw rebroadcasts, exactly one signature/artifact, and a subsequent failed settlement write fencing the owner; this is same-operation recovery, not a fresh payment.

Checkpoint fixture setup now remains lifecycle-valid at each awaited durable boundary (in-use before retained spend; terminal before recovery disposition). Existing terminal/import facts are retained rather than fabricated or compacted away. Raw persistence probes parse the new v3 envelope and explicit expected revisions.

The re-observation tests previously guessed that a fixed `setImmediate` settling turn had reached the receipt request. Authoritative storage introduces real awaited reload/commit work, so the tests now wait the actual mocked provider receipt-entry signal. The deadline case then advances its existing 30-second fake clock. This preserves the blocked physical request and late-after-close fencing assertions; it does not raise timeouts or add microtask loops. The isolated deadline pass was treated only as isolated evidence; the subsequent full 98-test domain suite passed with the entry signal fix.
