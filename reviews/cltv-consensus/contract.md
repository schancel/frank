## Concrete construction

Exact P2SH redeem: IF K_claim CHECKSIG ELSE T_X CHECKLOCKTIMEVERIFY DROP K_refund CHECKSIG ENDIF. T_X timestamp >=500000000. Refund spends with nLockTime=T_X, nSequence=fffffffe, ForkID0x41 digest of whole redeemScript and exact input value; claim uses true selector and the fixed ordinary key. Mine synthetic coinbase directly to deterministic fixture descriptors, mature via ordinary generatetodescriptor, then construct tiny P2SH outputs with clearly accounted change/fee. Wallet remains disabled; no existing key/data loaded. Record independent refund destination and exact principal/fee separately.

Use ordinary `generateblock("raw(6a)",[rawTransaction])` for forced candidate transaction validation including negative cases; RPC internally performs native TestBlockValidity, then mines and processes accepted blocks. ABC0.34.0 supports raw transactions here even when not in mempool. This avoids inventing block construction. Source: https://github.com/Bitcoin-ABC/bitcoin-abc/blob/v0.34.0/src/rpc/mining.cpp#L331-L460 . No manual header/merkle/PoW constructor or submission of bespoke blocks. Normal RPC validation is unchanged. Capture RPC error codes/messages, tip before/after, transaction inclusion and UTXO changes. testmempoolaccept results must remain labeled policy; native generateblock rejection/success is separate evidence.

Native positive control shares all unaffected fields. Reject wrong independent key as separate signature control, not timing evidence.
4. Race both orders using fresh outputs: claim included first makes refund spend invalid; refund included first makes claim invalid. Demonstrate claim branch remains valid after T_X when output unspent: refund maturity is not claim expiry. Distinguish absence from mempool from inability to become canonical. No atomic-swap claim.
