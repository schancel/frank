# Anchored funding observation capability

Base `c3e0fdbe` (local authoritative-pool integration, production squash `78fc61eb`). Parent scopes and reviews; Sol medium implements in `fix/funding-observation`. Repository-only offline fixtures; no live RPC/funds, secrets, resets, push, main merge or deployment. This bounded prerequisite implements the observation capability already required by the retained-funding contract. It is not funding-history persistence or full recovery completion.

## Outcome and ownership

The existing signer supplies receipt/account observations using its captured provider and receipt client. It currently exposes status-only `getStatus`, which collapses unknown execution to confirmed; that method must not be used as funding proof. Add a narrow typed funding-observation method on the existing signer, with pure exported result/input types as needed. No new package, transport, provider, global registry, store or signing operation. Preserve unrelated status consumers.

Inputs bind exact signed raw bytes and expected transaction hash, HD recipient, positive native chain ID and captured funder. Derive sender/value/nonce/data from signed bytes; validate signature/hash, signer affinity, exact recipient, positive value, empty calldata and native chain ID before RPC. Snapshot inputs before await. Canonical chain identity remains the caller's configuration ownership; this method's numeric ID serves native transaction validation only. Do not default to Monad. The installed wallet factory remains responsible for provider registry/checkpoint qualification; this method is not a replacement identity certificate.

Return a discriminated observation: unresolved (pending, unavailable, unknown execution or inconsistent chain observation), canonical included success/failure with receipt height/hash, or superseded with anchored sender nonce evidence. Included observations retain pinned sender nonce, recipient nonce and recipient balance plus account block height/hash. No receipt plus positive recipient balance cannot imply success. Supersession requires sender nonce strictly beyond the signed nonce at a coherent canonical anchor and absence of a matching receipt; it is reorg-sensitive evidence, not permanent finality. Unknown execution never returns success.

Use the existing receipt client and provider methods. Validate receipt identity, execution and safe nonnegative block height/nonempty correctly formed block hash. Compare its block to the provider's canonical block at that height. Pin all account reads to one explicit block and recheck its hash afterward; reject inconsistent, missing or replaced blocks. For receipt-less observations choose an explicit canonical head anchor before nonce/balance reads; repeat receipt lookup as necessary to avoid calling a newly included transaction superseded. Keep unavailable RPC distinct from invalid caller input. Do not swallow invalid signed input into a successful or pending result. A returned observation never mutates inventory or authorizes signing. The consuming owner will enforce lifetime/revision publication, so late returned facts cannot themselves change eligibility.

## Acceptance

Real offline ethers-signed transfers exercise the actual signer method with controlled receipt/provider responses. Prove included success and revert, pending with positive balance, unknown execution, wrong receipt identity, wrong recipient/signer/native chain/data/value, receipt/block mismatch, same-height replacement during account reads, RPC failure, coherent supersession and receipt appearing during supersession checks. Verify pinned block tags and no signing/broadcast/storage side effects. Test mutation of caller input while reads wait. Preserve existing signer construction/submission/status tests. Add fail-before evidence for the new desired proof boundary without reclassifying old getStatus as a new-policy bug.

Run focused signer suites and all configured typechecks; no broad whole-wallet sweep. Use existing dependency overlays, no installs or shared node_modules writes. Commit exact commands/results and source limits. Freeze clean revision for independent review; stop at handoff. Do not integrate. Parent owns final source review and the later persistent consumer contract.
