Add to `OwnedNegotiationJournalStore`:

- `listRecords(): Promise<readonly { readonly key: string; readonly raw: string }[]>` returns copied/frozen validated entries in key order; absent namespace returns an empty array without initialization.
- `readCoverage(chainIdentifier: string): Promise<number | undefined>` returns committed inclusive position, or absence without initialization.
- `compareAndSwapCoverage(chainIdentifier: string, expected: number | undefined, next: number): Promise<boolean>` atomically compares committed coverage for that chain and durably commits a monotonic position. Validate inputs before storage effects. False means a committed competing value; errors may be ambiguous and never imply absence. Equal expected/next is permitted; exact retry after an ambiguous write uses read/reconciliation, never guesses a greater position.

Both positions must be nonnegative safe integers; next cannot be less than expected or an existing committed value. Chain identifiers must be exact IDs in the shared protocol registry, not aliases/prefix inference. Registry membership does not assert a scanner exists. Account/local-key/host affinity stays in the existing namespace binding. Snapshot all input values before awaits. No mutable private maps escape.

## Format and lifecycle

Add exactly one optional key `coverage-v1`, serialized JSON with exact schema `{version: 1, positions: [{chainIdentifier, resumeFromInclusive}]}`. Positions are sorted lexically by canonical identifier, unique, at most 32 entries; entire metadata is at most 16384 UTF-8 bytes. Reject extra/missing fields, malformed numbers, duplicate/unknown/unsorted identifiers and excess bounds. Existing `binding-v1` is mandatory for every present namespace and remains unchanged. Absent coverage is legitimate for a journal created before scanning commits; a present corrupt record fails observably and is never repaired/reset. Unknown keys still reject. Full inventory validation precedes returning rows or coverage.

Coverage does not consume the signed-row budget (128 rows/8 MiB), and has its own stated bounds. Reads/listing and failed expected-value CAS must never initialize absent storage. First successful coverage CAS with expected undefined must atomically initialize binding plus coverage using the same strict IndexedDB transaction/Web Lock or native Level synchronous batch and existing exclusive directory owner. First signed-row initialization remains valid without coverage. Race either initializer against the other and preserve both winning facts. Existing journal CAS must preserve coverage and validate it; coverage CAS must preserve all signed rows. Capacity refusal preserves prior data and remains a recoverable refusal under existing queue policy.

Preserve strict browser transaction completion, cross-handle serialization, native process/module directory barriers, close/revocation and poisoned-error behavior. No adapter fallback, separate database, new mutable index, eviction, migration, or initialization on hydration. Existing older adapter code will reject the new metadata: document this additive format's reversal limitation and preserve stored data. No wire format changes. One shared validator owns metadata semantics; adapters retain their platform-specific atomicity.
