# Retain last-valid oracle valuations — Tier 3

Owner-confirmed outcome: retain the last valid AVU visibly marked stale when newly received data cannot produce a valid valuation; preserve original observation timestamps. Failed network requests retain the existing freshness/age policy and retry cadence rather than prematurely forcing stale. This supersedes the generic Pinia replacement proposal, preserved on archive/oracle-replacement-rejected. The plugin and all other stores remain unchanged.

Current shape: OracleCache owns persisted point history in oracle:v2 and keeps latest source metadata; OracleRates is a transient derived snapshot with one avuHash provenance shared by its asset rates and an independent avuSpot. Recursive publication accidentally retains unrelated nested fields. Target: one optional bounded, validated last-valid view inside that same cache metadata and Level save batch. Its hash/rates/priceAt/priceStale/at form a coherent bundle; spot may advance independently. Retained data is display cache, not authorization/spend state. No new store, service, hook, wallet schema, wire format, derivation, migration or reset.

Publication policy: compute once from merged source series. If a new calculation lacks a valid hash or loses a previously valued asset, hold the complete previous hash/rates/provenance bundle and set existing stale flags without changing its timestamps or fee-coverage basis. Spot retains its complete previous positive reading as stale on invalid input. Valid replacements clear obsolete unavailable flags. Partial old-rate/new-hash hybrids are prohibited. Existing history-current initialization guard remains; historical source/cache merging remains unchanged.

Persistence/restore: normal successful feed mutations capture the bounded view in existing cache metadata. Hydration derives current from latest inputs and the validated optional captured view, without writing, initializing, deleting or migrating records. Legacy caches without a view can seed an in-memory valid result, then capture it only on a later authorized normal feed mutation. If old invalid corrections already erased the only valid inputs before capture, show unavailable rather than inventing history or running an unbounded reverse scan. The view is reconstructible only while its original inputs and metadata remain. After a correction overwrites them, its saved provenance is a distinct historical display fact owned by this same cache: dropping it loses that display value, never keys or funds. No deletion is authorized. The optional additive view avoids a new durable financial model, while exact post-capture restart survives same-time corrections. Scope of metadata history/provenance is the captured bundle; no general feed journal is introduced.

Validation and bound: accept only typed supported-asset keys, finite positive values with non-future integer observation times, coherent hash provenance/fee coverage, and bounded entry/string/serialized sizes. Validate optional restored view before publication. Invalid views remain observable as an error without overwriting stored bytes; never trust invalid financial-rate provenance. Writer applies the same bounds before mutation. Keep one snapshot only, never chronological derived snapshots.

Allowed production files: app/src/stores/oracle.ts, app/src/stores/oracle-series.ts and a small colocated helper if validation/publication needs cohesive separation. Preserve pure wallet computeOracleRates, generic plugin, financial freshness thresholds, configured fallback, cache point merging, restore gates, suppression/flush/errors. Oracle-only current is an explicitly immutable reactive view returned on restore, so the existing documented Vue/Pinia reactive patch semantics replace it atomically. Normal publication uses function-form assignments. Display age honors existing priceStale flags including age zero.

Acceptance: available -> zero/negative/missing -> available; whole-bundle coherence and independent spot; explicit stale labels/original timestamps; valid replacement removes unavailable artifacts; failed fetch preserves age policy; no valid history produces no invented values; latest/history/actual-plugin restoration; real Level close/reopen after captured sole valid point was overwritten; read-only hydration performs no writes; malformed/oversized/nonfinite/future/incoherent saved snapshot rejected without writes; financial stamp resolver refuses held-stale rates and retains existing threshold/fallback behavior. Existing financial pending-operation/reservation restoration tests remain unchanged. Fail-before/pass-after, changed-file formatting, typecheck and independent review precede landing. Tests/build/runtime await root capacity.

Root owns scheduling, unresolved scope and integration. No production or funded actions are authorized. Rollback reverts display/cache code; no account/private-key deletion. Snapshot addition is optional and inside the existing metadata namespace, with no migration, dual writer or reset path.
