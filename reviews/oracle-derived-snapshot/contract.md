# Owner-policy revision — design only, supersedes the replacement proposal below

Owner decision: keep the last valid AVU visibly marked stale, retaining original observation timestamps. The generic Pinia restore-replacement proposal is cancelled: app/src/boot/pinia.ts and all other stores remain unchanged. The uncommitted test drafts currently assert the superseded replacement policy and are retained as investigation artifacts only; they are not acceptance requirements and must be revised before implementation. No production source has been edited.

Current shape: OracleCache is the single persisted source of point history; it retains only the latest basket/electricity/series metadata, and same-timestamp corrections replace earlier points. OracleRates is transient and has one avuHash provenance for every asset rate, plus a separate avuSpot reading. Target shape should keep these owners and existing financial freshness thresholds. The proposed publication policy below still needs root approval.

Proposed coherent publication: treat {at, avuHash, rates, priceAt, priceStale} as one hash-derived bundle. On an invalid new hash or loss of a previously valid asset rate, retain the prior coherent bundle, preserve its at/oldestInputAt/priceAt, and mark its hash/rates stale; do not attach old rates to a new hash. Spot is independent: retain its last positive {kwhPerValue, pricePerKwh, at} as stale when a new reading is zero/negative/unavailable. A valid replacement is assigned as a complete object so an obsolete unavailable flag cannot survive. This conservative bundle hold can delay otherwise fresh asset displays while another previously valued asset is invalid; root must accept that tradeoff or choose explicit recomputation from held valid inputs instead.

Source-local implementation sketch: an oracle-only publication helper, function-form latest/history assignments preserving cache merge and the existing history guard, and an oracle-only reactive current value in the restore result (the installed Pinia plugin replaces reactive subpatches). Keep generic plugin, restore gates, save suppression and errors unchanged. Update the existing display age getter to honor explicit priceStale flags even before age thresholds, including age zero. Existing stamp resolver already rejects hash.stale/priceStale and must retain its thresholds, original timestamps, fee basis and configured fallback behavior.

Reconstruction limits: at() gives logarithmic floor lookup but validity is not monotonic, so it cannot locate an arbitrarily old last-valid snapshot by binary search alone. A bounded reverse event search can run only when current calculation is invalid (latest requests with valid data stay on the one-computation path), but a hard search cap may miss valid retained history. A complete unbounded historical search risks reopening cost. More fundamentally, the persisted cache cannot reconstruct values whose only valid point was overwritten by a same-timestamp invalid correction, nor an old basket definition removed by newer metadata. Exact last-valid reconstruction for those cases requires preserving additional durable provenance; no such new durable change is authorized. Do not silently claim restart equivalence outside retained compatible history. Root must select the reconstruction guarantee and bound before production work.

Acceptance after that decision: positive -> zero/negative/missing -> valid again; coherent held bundle and independent spot; all held values visibly stale with unchanged observation times; successful replacement clears stale/unavailable artifacts; failed refresh retains history and does not freshen provenance; latest/history/real Level restore agree for reconstructible histories; no valid history invents a number; unchanged financial staleness tests; no plugin/other-store changes. Source-only design is held for approval; frozen sidebar work is untouched.
