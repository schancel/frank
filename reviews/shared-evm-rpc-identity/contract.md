## Behavior

Preserve explicit canonical configuration consistency checks and existing public-network pinned checkpoints. Regtest operator checkpoint must have a safe integer height strictly greater than zero and a valid 32-byte hexadecimal hash. Missing, zero, negative, fractional or malformed operator values reject before network work. Public registry checkpoints cannot be overridden by a supplied operator value.

Each invocation must obtain current native-ID and checkpoint responses from the exact supplied provider using its ordinary raw JSON-RPC request surface (`eth_chainId`, `eth_getBlockByNumber` with an explicit numeric block tag and no transaction bodies), rather than treating ethers network/block caches as a fresh qualification. Validate external response shapes, exact native ID, requested block height and full hash; missing/malformed/mismatched responses fail visibly. A cached successful earlier invocation must not bypass a later mismatch. Preserve provider transport behavior; add no retry loop, background task or second provider.

Capture immutable configuration/checkpoint values before asynchronous calls. Invoke the supplied lifecycle assertion before and after each asynchronous boundary, and before success; a revoked session or mutation of caller-owned inputs must not redirect the in-flight check. The function reports success only for this observation and lifetime; it does not issue a durable certificate or promise the upstream can never change.

Use narrow typed capabilities and the existing protocol registry. No universal provider framework, new package, global verifier cache, chain-name special cases or native-chain-ID network lookup. No persisted or wire format changes. No destructive reset or migration. No new chain capability or supported-network claim.
