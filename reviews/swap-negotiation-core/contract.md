# S5a: authenticated swap negotiation core

Root-authored Tier-3 contract. Exact base `3951bbf2557a31d7380a3ae6b07431f966e031b5`; branch `feat/swap-negotiation-core`. Implementation: integrate_swap_proofs, GPT-6.1 Sol medium. Independent review follows. Local candidate only: no push, main merge, deployment or funded execution.

## Outcome and ownership

The existing swap package owns signed transcript framing and deterministic reduction but has no concrete offer/response schema. Add a pure, bounded negotiation entry point owning offer/accept/reject encoding, signature verification and reduction. This is the immediately usable predecessor of application-plugin transport and UI/runtime wiring, not a completed swap product. Wallet custody, generic messaging and chain execution do not acquire feature rules. No HTLC, new threshold protocol, signing-session persistence, financial execution or automatic acceptance.

Use a separate `src/negotiation.ts` entry (cohesive private helpers permitted), leaving existing core exports/behavior unchanged. Depend on `@frank/codec` canonical primitives and algorithm-1 verifier; no wallet, Vue, Pinia, bot-framework or host storage imports. Tests may use the existing real identity signer through a test-only import to prove interoperability. Do not add a dependency merely to obtain a mock signer.

## Frozen schema

Manifest-local message types 1=Offer, 2=Accept, 3=Reject; roles 0=A/XEC depositor, 1=B/EVM depositor; lane 0; existing event protocol version 1. Each payload is canonical CBOR with exact integer-key maps, no extra fields:

- Offer: 0 payloadVersion=1, 1 pairPolicyVersion=1, 2 conversationId=bstr16, 3 ordered parties=[A compressed secp256k1 key bstr33, B key bstr33], 4 XEC chainIdentifier=tstr, 5 EVM chainIdentifier=tstr, 6 XEC principal=uint64 strictly positive, 7 EVM principal=big-endian bstr32 strictly positive, 8 expiry=uint64 Unix seconds.
- Accept/Reject: 0 payloadVersion=1, 1 conversationId=bstr16, 2 responder B compressed key=bstr33, 3 offerEventId=bstr32, 4 termsHash=bstr32. Message type distinguishes decisions.

Validate actual curve-point encodings, distinct parties and exact lengths. Use codec key validation/primitives rather than a new public-key implementation. Monetary API quantities use bigint; never JS floats or display units. Offer execution configuration excludes J/T, chosen inputs/nonces, contract deployments, runtime code hashes, fee budgets, timestamps of actual funding and recovery authorizations. These belong to the later explicit preparation/funding contract.

Pair policy is injected explicitly and validates registry canonical identifiers and family/capability requirements. Initial supported policy is exactly `xec-testnet` / `monad-testnet`; separately named local proof policy is exactly `xec-regtest` / `monad-regtest`. No defaults, aliases, prefix inference or native-ID substitution; do not independently redefine shared registry facts. Reject mismatched ordered chain pairs. Inspect the existing registry accessor before selecting the narrowest import; report if a new dependency or shared-source edit is needed.

Identity key ID is `SHA256(frame("frank/swap-identity-key-id/v1", compressedKey33))`. Preserve existing event ID and signature-preimage domains. Algorithm 1 is central strict-DER low-S ECDSA over SHA256: hash the existing framed preimage exactly once and verify using `verifyAlgorithm1`; existing identity `signHash` signs that digest. Expose a narrow injected asynchronous digest signer to builders, validate its returned signature before returning a signed event, and snapshot mutable input before any await. Never use an Ethereum message prefix. The external signer capability is not permission to sign financial transactions.

Terms hash is `SHA256(frame("frank/swap-negotiation-terms/v1", 0x01 || swapId32 || laneIdByte || canonicalOfferPayloadBytes))`. Fix golden vectors for key ID, payload bytes, terms hash, signature digest and event bytes. Swap ID is a new 32-byte identifier supplied by the operation creator and carried on the wire; this pure layer must not generate IDs or invent a derivation.

Offer is A sequence 0 with zero previous hash and no prerequisites. Accept/Reject is B sequence 0 with zero previous hash and exactly the offer event ID as its prerequisite. No later sender-chain entries are valid negotiation messages. Enforce those restrictions before reduction so invalid orphan events cannot remain buffered as plausible negotiation.

## Authenticated context and state

Independent design review clarifications: prevalidate EVERY event's full canonical payload, context, roles, sequence and exact prerequisite shape before calling the core reducer. Descriptor callbacks are insufficient because missing-prerequisite orphans never reach them. Bound a negotiation batch to 64 input events, each at most 1,024 encoded bytes, at most 65,536 aggregate bytes, and each payload at most 512 bytes before signature verification. Reject excess, never truncate; duplicate inputs still count against admission limits. These are feature-local limits, not changes to core transcript limits. Expose an explicit payload decoding path accepting the enclosing codec `NestedItemBudget` so transport can charge traversal to its existing counters. An explicitly named standalone path may create a standalone budget; received-message callers must not reset it.

Registry scope clarification: import the authoritative JSON directly for the narrow pair checks, as existing codec projections do. No wallet import or registry-source modification. Package tsconfig changes are allowed only if actually needed for this JSON import (the base already enables resolveJsonModule/esModuleInterop).

Downstream plugin seam clarification: expose a schema/self-contained-signature decoder taking bytes, an explicit installed pair policy and the enclosing NestedItemBudget, without requiring a journal or invented counterparty. Offers contain their signer A and both parties; responses contain their signer B and may arrive before an offer. This decoder validates the complete canonical schema, point/key ID, event role/sequence/prerequisites and signer signature, but does not confer authenticated host context or operation admission. Full-context decoding binds its result to the expected swap/conversation/ordered parties; the authenticated helper additionally binds the receive record. Reuse one payload parse and its existing budget, with no reset or double charge. Test orphan-response schema decoding without A, plus full-context wrong-party/swap/conversation rejection. Wire bytes and cryptographic domains stay unchanged.

Require exact expected swap ID, actual conversation ID, ordered party keys and explicit pair policy when constructing the negotiation manifest/reducer context. Missing conversation context rejects; do not derive a default-direct ID. A host-facing validation helper additionally accepts authenticated sender/recipient public keys and conversation for an incoming record, and verifies equality with the event role and counterparty before any reducer state effect. This pure contract does not establish provenance itself; callers must use canonical authenticated receive records, never profile lookups or arbitrary restored Message objects. Validate local outbound replay under an explicitly named direction rather than silently exchanging sender/recipient.

Reuse existing signed-event verification, sender-chain and equivocation logic. Missing prerequisite offers buffer a structurally/authentically valid response; identical retransmissions deduplicate. Different offers for the same A sequence or conflicting B decisions fail closed. Every reference and terms hash must match the actual offer before a response applies. No acceptance state is usable when the journal reports any violation, even if a partial state was computed. Expose that distinction clearly in the negotiation result.

Separate historical signed state from current eligibility. Pure reduction has no ambient clock. A separate eligibility function receives explicit current Unix seconds: expiry is exclusive (`now < expiry`), blocks new preparation after expiry, and never erases signed acceptance or implies funds/reservations may be released. A signed acceptance received/replayed after expiry remains historical evidence, not current authority. Negotiation alone never authorizes funding, release or deletion.
