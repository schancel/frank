## Outcome and ownership

S5a validates signed negotiation events but does not retain authenticated admission across restart. S5b independently implements inert message transport/previews. This stage supplies the usable headless journal engine for one immutable negotiation context, with an injected atomic durable row capability. It does not install storage or runtime in app/bots. Pure feature code owns admission, exact record schema, reconstruction and duplicate/conflict semantics; host owns verified outer-message provenance, account incarnation, lifecycle and the concrete storage implementation. A later separately reviewed adapter/host stage qualifies actual storage durability and bounds the total number of negotiations per account before production installation.

No keys, funding, reservations, secret custody, clock, automatic acceptance, outgoing signing, generic inbox framework or financial authorization. Existing wallet financial owners remain authoritative. Negotiation acceptance is historical evidence only. Read/hydration never admits arbitrary presentation projections. H2 reset behavior remains an owner decision; this engine supplies no reset-resistant financial recovery claim.

## Facade and immutable context

New separate `packages/swap-protocol/src/negotiation-journal.ts` entry, cohesive private helpers if needed. Do not modify S5a, core index, S5b plugin, wallet or host. Use codec, existing negotiation validators/reducer and the authoritative chain JSON only. No browser/Node storage or wallet/framework imports.

Bind each instance to explicit owner `{accountIncarnation: string, localPublicKey: Uint8Array, messagingChainIdentifier: string}` and full existing NegotiationContext (swap ID, actual wire conversation ID, ordered parties, explicit pair policy). Incarnation is a nonempty opaque host reference, UTF-8 bounded to 256 bytes; never infer it from a key or invent an account ID. Messaging chain must exactly match an authoritative registry id. Local key must be one of the two distinct valid party keys. Validate and snapshot the full binding, including Buffer inputs, synchronously before any await. No auto-derivation of conversation or network defaults. Orphan-response host context will be supplied explicitly from canonical sender/recipient; this engine never invents absent party information.

Expose a deterministic row key as a domain-separated SHA256 of unambiguous length-framed version, owner and negotiation context. Use domain `frank/swap-negotiation-journal-key/v1`. Document exact framing and fix a golden vector. This key is a storage identifier, not a confidentiality boundary. No randomness or account-private salt is needed for this local public-evidence row; never export it as a cross-user identifier.

The narrow store capability is `read(key): Promise<string | undefined>` and `compareAndSwap(key, expectedRaw: string | undefined, nextRaw: string): Promise<boolean>`. It MUST offer linearizable compare-and-swap across handles, durable success before true, committed reads or observable failure, and no implicit initialization on absent reads. False means another committed writer won; an exception may mean an ambiguous write and must propagate without claiming absence. Document this contract prominently. S5c1 tests a faithful in-memory implementation for algorithmic evidence only. No production memory fallback. Do not wrap this in a universal service interface.

## Record and admission

Version 1 exact JSON record contains the full normalized owner/context binding and a bounded array of evidence entries. Normalize byte fields to lowercase hex. Each entry contains original event bytes, authenticated sender/recipient keys, explicit incoming/outbound-replay direction, canonical message ID (16 bytes) and stamped payload digest (32 bytes). Distinguish the stamped payload digest from contentDigest; do not relabel one as the other. Conversation/local identity belong to the immutable binding and must be revalidated for every entry. Retain no unbounded list of duplicate delivery metadata. The first valid delivery metadata is sufficient; identical event bytes under another valid delivery are idempotent after authenticating that delivery.

Use original signed bytes as authoritative; do not persist derived accepted/status flags. Strictly validate exact shape/types/lengths, known version, owner/context equality, every event signature and each authenticated binding on read/reopen. A malformed or mismatched existing row is an observable error, never absence or a replacement opportunity. Bound raw JSON before parsing to 262144 UTF-8 bytes, bound entry count to S5a's 64 and aggregate original event bytes to 65536. Check runtime input types and bounds before copying or expensive validation. No compatibility parser, migration, auto-reset or pruning.

Admission receives explicit authenticated delivery context and event bytes from a trusted canonical host. The delivery assertion MUST additionally include messagingChainIdentifier and match the bound owner.messagingChainIdentifier exactly; S5a authenticated context alone does not carry that chain. Persist the chain once in the immutable row binding, not redundantly per entry. The engine checks supplied assertions but cannot establish outer-envelope provenance itself. Snapshot all input before the first store await. Require canonical message ID and payload digest; reject missing fields and wrong local identity, direction, conversation, party or swap. Reuse validateAuthenticatedNegotiationEvent; transport decode budgets belong to S5b, whereas this separately invoked journal operation uses explicitly standalone validation/reconstruction budgets. Do not reset an enclosing transport budget because none is supplied here.

Read fresh raw row, validate it completely, authenticate the new entry, merge, reconstruct with S5a, serialize exact normalized record and CAS. Retry CAS-false from a fresh read up to eight attempts, then return a distinct observable contention error. Do not retry storage exceptions automatically. Exact duplicates perform no write and remain valid even at capacity. Distinct valid signed conflicts must be retained so S5a returns its violation; do not overwrite the old offer/response or reject the new evidence merely because reduction detects equivocation. Invalid signatures/context never enter storage. Capacity errors preserve the existing bytes and are distinct from corruption/storage failures; never evict evidence. A response before an offer remains buffered and becomes usable only when the correct offer is later admitted. Different encodings with valid distinct signatures count as distinct bytes subject to the same bound; reduction remains authoritative about semantic duplicates/conflicts.

Expose a pure inspectNegotiationJournalRecord(raw) helper for the separately owned storage adapters. It must apply the same pre-parse bounds, exact schema, canonical binding/key, signature and authenticated-context validation as instance reads, returning the validated row key plus owned owner/context/evidence/reduction. It does not establish outer provenance. Adapters will compare its account/local-key binding and row key with their expected owner/requested key; the helper itself must never silently select an expected host owner. Factor the existing parser rather than duplicate it. Test malformed input and mutation of returned values on this public seam. No concrete storage or account-wide limits enter this stage.

Read/reconstruction is read-only; absent row yields an explicit empty result, with no put/default record. Returned arrays/bytes must not alias internal or later persisted state. Repeated read must observe committed updates rather than a competing authoritative cache. If success commits but acknowledgment throws, caller sees failure; a new instance retrying identical evidence discovers it without duplicate growth. No release/delete API in this stage. Host lifecycle revocation and per-account capacity/retention are mandatory successor contracts before install.

## Reversal and successors

Current durable shape is absent; target is one bounded immutable-context evidence row, not an account-wide mutable acceptance index. Immediate successors own qualified browser/native CAS adapters and account-wide admission limits, then authenticated polling/streaming/bot installation and outbound replay. Host must decide pre-activation history handling and distinguish account restoration from incarnation rebinding before dispatch. Local admission metadata is trusted local application state on reopen, revalidated against signed inner bytes; hostile store mutation/rollback is not solved and no reauthentication of stored outer envelopes is claimed. This matches the stated local-store trust boundary, not stronger cryptographic provenance. Financial execution requires separate explicit consent, retained artifacts and custody lifecycle protections. Reversal before host install is deleting this unused entry; after install requires coordinated reader/writer removal with no deletion of recovery evidence.
