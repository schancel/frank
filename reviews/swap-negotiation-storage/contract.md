## Capacity and CAS

Freeze the initial local account envelope at128 rows and8388608 UTF-8 serialized row bytes, with S5c1's262144 per-row limit. Export constants; these are storage policy, not wire facts. Derive count/bytes from actual records, never maintain a competing mutable counter. Metadata is separate from row capacity. Reject unknown record keys, malformed metadata/rows, affinity mismatches and invalid key encodings visibly. A proposal with noncanonical row keys/hex fields, invalid schema or excessive size is rejected before database creation or expensive storage work. JSON whitespace/property order are not additional canonicality requirements: use the strict S5c1 inspector as authority, preserve accepted raw strings exactly for CAS, and do not add a second JSON canonicalizer or writer-order restriction.

CAS compares exact raw expected value before capacity evaluation. A concurrent insertion yields false, not capacity. A new row counts toward both limits; updates count the replacement size and remain possible at row-count capacity. Existing evidence is never evicted. Duplicate journal admissions remain no-write reads. Ordinary comparison/capacity refusal must not poison the owner. Successful CAS means committed durable data; an exception may mean commit occurred. Do not automatically retry an ambiguous write or represent it as absence. Uncertain storage/write failure poisons that handle before queued later operations can run; close/reopen is required to reconcile original evidence. Missing records inside a valid initialized database are normal; missing binding in an existing namespace is incomplete initialization and an error.

Keep schema version1 and one records store with an out-of-line metadata key distinct from journal row keys. Factory/read absent inspection must create no database, metadata or defaults. Existing-only opens abort unexpected onupgradeneeded. Validate schema/version/store configuration and binding before publishing a connection; no readwrite capability probe on reopening.

A namespace-scoped exclusive Web Lock covers every NEW connection's opening/initial inspection and first initialization. It prevents a second tab observing the gap between schema creation and strict first-row commit. Normal reads/CAS on a qualified connection need only IDB transactions. Prevalidate first proposed row; while holding the namespace lock, create schema only if this open actually creates the DB, then commit full binding and first row together in one verified strict readwrite transaction. Await transaction completion before releasing lock/publishing. An existing namespace with missing binding is never initialized or repaired. If creation is interrupted in the schema/binding gap, leave the incomplete namespace observable on reopen.

Compare target, validate binding, check actual capacity and write within ONE readwrite transaction; callbacks doing transaction work stay synchronous (no awaited signature validation between requests). Prevalidation is pure/synchronous; transaction reads may perform synchronous row checks. Require actual transaction.durability==='strict', and await completion rather than request success. An empty later strict transaction is not a substitute for strict first-row commit. Never use lock stealing, timeouts-as-success or process-local initialization locks. Abandoned/blocked/error opens abort any later upgrade and close late connections before they can publish or initialize. Close while waiting for a lock/open must prevent late publication, with all owned cleanup observed.
